# Outfit Asset: resizing and cloth simulation (UE 5.8.2 source)

## The answer in five lines

1. An Outfit Asset never blends sizes. It picks one stored source size (with one source body, always that one) and warps the garment from that body's shape to the new body's shape, using a smooth space-warp fixed at about 1,500 matching points on the two bodies.
2. The warp moves the simulation mesh if there is one (the visible mesh then follows it), otherwise the visible mesh; skin weights are then re-copied from the new body. Both bodies must be MetaHuman merged head-and-body meshes with identical vertex numbering.
3. Nothing limits bodies far from the source: the warp simply stretches further, with no tailoring logic. Epic's own note says to add another source size when results are poor; for Rocco (heavy) and Sam (lean) from one source, expect plain stretching.
4. The forum claim is confirmed: a full ("Production") MetaHuman assembly bakes every outfit into a plain skeletal mesh by a function documented to drop all cloth simulation.
5. Simulation survives only in the editor's Preview assembly (which cannot be saved or cooked), or if the game puts the resized Outfit Asset itself on a Chaos Cloth component, outside the MetaHuman assembly (likely, untested).

D = read in code; I = inference. Paths are relative to `Engine\`; a bare file name repeats the folder of its first full mention.

## Question 1: resizing

- D Body data is a name-to-number table `Measurements` in `UChaosOutfitAssetBodyUserData` on the merged body mesh: `Plugins/ChaosOutfitAsset/Source/ChaosOutfitAssetEngine/Public/ChaosOutfitAsset/BodyUserData.h:8-20`. The MetaHuman editor writes it when generating the merged mesh: `Plugins/MetaHuman/MetaHumanCharacter/Source/MetaHumanCharacterEditor/Private/MetaHumanCharacterEditorSubsystem.cpp:2116-2133, 5021-5030`.
- D A "size" is a source garment, a size name, source body parts and `NumResizingInterpolationPoints` (default 1500): `Plugins/ChaosOutfitAsset/Source/ChaosOutfitAssetEngine/Public/ChaosOutfitAsset/SizedOutfitSource.h:26-50`, `Plugins/ChaosOutfitAsset/Source/ChaosOutfitAssetEngine/Public/ChaosOutfitAsset/OutfitCollection.h:65`. The comment at `SizedOutfitSource.h:44-47` recommends "adding a new Size" when more points do not help.
- D Adding a size copies the body's measurements and computes the warp weights from the body's LOD0, editor-only: `Plugins/ChaosOutfitAsset/Source/ChaosOutfitAssetEngine/Private/ChaosOutfitAsset/Outfit.cpp:407-420, 424-442`.
- D Choosing a size: one size means size 0, no test (`Plugins/ChaosOutfitAsset/Source/ChaosOutfitAssetEngine/Private/ChaosOutfitAsset/CollectionOutfitFacade.cpp:597-601`). Otherwise each size is scored by a body-shape classifier on Hip, Bust/Chest, Underbust, Waist, Neck to Waist, Rise, Inseam (`:214-284`): points for matching protrusion, shape and proportion, minus 5 per cm of hip difference (`:287-385`); the top score wins (`:606-621`). No interpolation between sizes. I: the shape labels look swapped (a narrow waist is called "Circle", `:263-270`); harmless with one size.
- D The filter node keeps only the chosen size; a named size wins over matching (`Plugins/ChaosOutfitAsset/Source/ChaosOutfitAssetDataflowNodes/Private/ChaosOutfitAsset/FilterSizedOutfitNode.cpp:34-64`). MetaHuman's "SourceSizeOverride" feeds `OverrideBodySizeName`: `Plugins/MetaHuman/MetaHumanCharacter/Source/MetaHumanDefaultEditorPipeline/Private/Item/MetaHumanOutfitEditorPipeline.cpp:105-109`.
- D The warp (RBF): target positions are read from the new body at the source's sample vertex numbers, falling back to the source position if a number is invalid (`Plugins/Experimental/MeshResizing/Source/MeshResizingCore/Private/MeshResizing/RBFInterpolation.cpp:369-390`); each point moves by a multiquadric sum plus a linear term (`:28-46`):
  `const float FunctionValue = FMath::Sqrt(FVector3f::DotProduct(PositionDelta, PositionDelta) + 1);`
  I: this extrapolates roughly linearly beyond the source body; no clamp exists in this code.
- D What moves: with simulation data, the sim positions and normals (`Plugins/ChaosClothAssetDataflowNodes/Source/ChaosClothAssetDataflowNodes/Private/ChaosClothAsset/ApplyResizingNode.cpp:55-91`); the render mesh only when there is no sim data or `bForceApplyToRenderMesh` (`:93-112`, `Plugins/ChaosClothAssetDataflowNodes/Source/ChaosClothAssetDataflowNodes/Public/ChaosClothAsset/ApplyResizingNode.h:40-42`). The render mesh then follows via the proxy deformer (`Plugins/ChaosClothAssetDataflowNodes/Source/ChaosClothAssetDataflowNodes/Public/ChaosClothAsset/ApplyProxyDeformerNode.h:9-11`). The target "Must have matching vertices with SourceMesh" (`ApplyResizingNode.h:28-30`).
- I Probable bug: custom-region data is built from the target body, not the source (`ApplyResizingNode.cpp:79, 100`, `InTargetSKM->GetMeshDescription`).
- Templates (binary; only names readable, not wiring): ResizeOutfitTemplate names FilterSizedOutfit, GetOutfitRBFInterpolationData, ApplyResizing, ApplyProxyDeformer, TransferSkinWeights (render/sim; closest point or inpaint), CorrectSkinWeights (prune, relax, hammer, clamp, normalize), UV resizing and a StripSimMesh branch. ## Question 2: simulation in wardrobe and assembly

- D A wardrobe item holds a principal asset and an item pipeline (`Plugins/MetaHuman/MetaHumanCharacter/Source/MetaHumanCharacterPalette/Public/MetaHumanWardrobeItem.h:46, 68`); outfit slots accept `UChaosOutfitAsset` (`MetaHumanDefaultEditorPipelineBase.cpp:276-287`).
- D Build: per character, a new Outfit Asset runs the resize graph (`MetaHumanOutfitEditorPipeline.cpp:63-114`). Then:
  `// For Production quality, we bake to meshes, because Outfits can't yet be cooked`
  `if (ClothForCharacter->ExportToSkeletalMesh(*SkeletalMesh))` (`:145-146`, block `:141-152`). Preview keeps the Outfit Asset (`:154-158`).
- D The bake "excludes all clothing simulation data" (`Plugins/ChaosClothAsset/Source/ChaosClothAssetEngine/Public/ChaosClothAsset/ClothAssetBase.h:353-359`); the converter reads only render vertices (`Plugins/ChaosClothAsset/Source/ChaosClothAssetTools/Private/ChaosClothAsset/SkeletalMeshConverter.cpp:57-66`) and builds a plain skeletal mesh (`:138-142`).
- D Assembly passes either the Outfit or the baked mesh (`Plugins/MetaHuman/MetaHumanCharacter/Source/MetaHumanDefaultPipeline/Private/Item/MetaHumanOutfitPipeline.cpp:88-89`); an Outfit goes on a `UChaosClothComponent`, a baked mesh on a `USkeletalMeshComponent` (`Plugins/MetaHuman/MetaHumanCharacter/Source/MetaHumanDefaultEditorPipeline/Private/MetaHumanDefaultEditorPipelineActor.cpp:269-299`; `MetaHumanDefaultEditorPipelineLegacy.cpp:371-399`; `MetaHumanOutfitPipeline.cpp:164-185`).
- D Collections default to Production (`Plugins/MetaHuman/MetaHumanCharacter/Source/MetaHumanCharacterPalette/Public/MetaHumanCollection.h:318-326`); Preview is the editor's transient copy (`MetaHumanCharacterEditorSubsystem.cpp:1162-1163`) and its built data is cleared on save (`Plugins/MetaHuman/MetaHumanCharacter/Source/MetaHumanCharacterPalette/Private/MetaHumanCollection.cpp:566-575`).
- D Even Preview strips the sim mesh when the character has no face DNA (`MetaHumanDefaultEditorPipelineBase.cpp:454-455`). The crowd pipeline bakes the same way (`Plugins/MetaHuman/MetaHumanCrowd/Source/MetaHumanCrowdEditor/Private/Item/MetaHumanCrowdOutfitEditorPipeline.cpp:427`).
- D The Outfit Asset type does cook in 5.8: cooked render data (`Plugins/ChaosOutfitAsset/Source/ChaosOutfitAssetEngine/Private/ChaosOutfitAsset/OutfitAsset.cpp:282-335`) and sim pieces trimmed of render fields (`Outfit.cpp:179-193`). I: the "can't yet be cooked" comment looks stale; a resized Outfit Asset placed by the game on its own Chaos Cloth component should keep simulation when packaged. A custom item pipeline overriding the virtual `BuildItem` (`Plugins/MetaHuman/MetaHumanCharacter/Source/MetaHumanDefaultEditorPipeline/Public/Item/MetaHumanOutfitEditorPipeline.h:61`) could also skip the bake.

Verdict: the code confirms the forum claim for every standard saved assembly.

## 3. The bulk rule (Kiln: python/run_prune.py; regression_gate.py prune() calls it)

A run folder loses its .obj .mtl .fbx .drape .zprj .png .jpg .exr .abc .glb .gltf .blend .exe .pdb .ply .stl files only when all of these hold:
- it has a numbers file (.json, .jsonl or .csv, not *plan.json);
- there is no KEEP file at its top, and KILN_KEEP_RUNS is not 1 (or --keep);
- retention.json does not protect or hold it;
- the jobs, baseline, HASHES.txt or an approval do not name it;
- the file itself is not named by any report;
- the file is not inside a git worktree;
- (sweep only) nothing in the run was written in the last 24 hours.

Scripts, logs, numbers and plans always stay. Writing happens only under F:/LedgerTools or C:/LedgerTools.
- The gate: at the end of every run without --keep, as before, now with those protections. The running gate's per-job children never call prune, so the gate running today was not affected.
- Helpers' runs: `python F:/LedgerTools/tool-dev/kiln/python/run_prune.py sweep F:/LedgerTools/tool-dev/runs` (the same for each kiln-lanes/*/runs-lane). A dry sweep today would free 110 MB (fixer-r7's meshes; LOOP.md names only its script). Tomorrow, after the 24-hour wait, most of the other heavy files in runs (about 0.4 GB) would go, plus what runs-lane holds.

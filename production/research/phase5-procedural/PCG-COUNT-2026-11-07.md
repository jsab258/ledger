# What a cooked level really holds of a saved PCG result: one count (7 November 2026)

Phase 5 research, measured, not built: PCG-RESULT-HOME-2026-11-03.md and PCG-SOURCE-ANSWERS-2026-11-07.md read the answer from the source and left it unverified "until one packaged count". A throwaway project on Unreal 5.8.2, never ue-probe; script tools/ue/pcg_count_spike.py; nothing of it in the game. Reference: none found (Epic's source and pages, those two notes). Not given a fresh review: it sets no target; phase 5's design, when written, gets one.

## Questions, written first

1. With a graph's Should Cook off and its result saved in a level, do the placed meshes reach the packaged game?
2. Do the graph and the PCG component go, as the header says?
3. Do two generations on one machine give the same transforms?

## Method

One graph: Create Points Grid (140 by 140), Transform Points (random offset and turn), Static Mesh Spawner (the engine's cube), CPU only. One PCG volume in a plain blank level, On Demand. Generated, read every instance's transform, cleared until no instanced component remained, generated again, compared; Should Cook off; saved; cooked and packaged Development for Windows (27 s, the project's own new cache); the packaged game run offscreen with `obj list class=` for each kind.

## Results

## What it means for the design (nothing decided)

The "saved in the editor, no generator shipped" recommendation stands on a count now, not only a reading. Phase 5's own count must expect an inert PCG component on each volume; if the design wants none, Clear PCG Link (a plain actor) is the untested way. Whether the leftover component could ever start generating with no graph was not tested; On Demand was set and no instance was added in the short run (the size is one reading, one moment).

## Not reached

Whether the instances were drawn: no picture taken; the run is offscreen. Two machines. Nanite (the project had it off and the cube has no Nanite build), so plain against hierarchical instancing is not answered. Partition, grammar, a real street's size, memory and frame time.

## Tries and leftovers

Two tries, both spent, on the spike's own start: -ExecutePythonScript makes the editor quit when the script returns, so a tick-driven script never finishes (a setup slip, seen at once); then LevelEditorSubsystem.new_level, from the open-world start map, failed to save and the editor crashed (access violation, the level editor's own code, no symbols, cause not read). A blank plain level through EditorLoadingAndSavingUtils worked first time. The project (2.18 GB, C:/LedgerTools/pcg-count-2026-11-07) was deleted after this note, as the session's own leftover.

# Moving mouths while the characters speak (research, 30 September 2026)

Asked: how can three MetaHumans' lips move roughly in time with run-time TTS chunks and pre-made wavs, in a packaged UE 5.8 game, free and on the allowlist?

## The answer

Use Epic's own streaming speech-to-face solver. It ships inside the installed engine (5.8.2) as a hidden beta plugin, "Streaming Audio Driven Animation" (StreamingADA, module SpeechAnimationSolver). It takes float audio in any chunk size and sample rate. For every 20 ms of speech it returns 81 MetaHuman face controls (jaw, lips, tongue, brows, blinks, 12 moods), running on Unreal's ONNX runtime on the processor or through DirectML on the graphics card. It is prebuilt for packaged games, so our C++ can feed it the TTS chunks we already queue: no Live Link, no microphone, no download, under the Unreal EULA. Epic's documented routes do not fit: the offline solve is editor-only, and the real-time Live Link source only hears an input device. The open alternatives fail our rules or this PC. Audio2Face-3D needs an NVIDIA card (this PC has an AMD RX 6700), and its models carry NVIDIA's own licence; OVR LipSync is proprietary and end-of-life; Rhubarb needs a whole file. Build an amplitude-driven jaw first as the fallback (half a day), then add the solver on top. Its cost per frame, and whether its model gets cooked into the package, are unmeasured and are the first things to check.

## Options

**1. Epic's streaming solver (recommended).** `FSpeechAnimationSolverV4` is public and exported. Feed it `FSpeechAnimationAudioFrame` (samples, rate, channels; `bContiguous=false` at each line's start; `Mood`; `Lookahead` 80 ms). It resamples to 16 kHz mono and outputs 50 frames a second from `/StreamingADA/xsada_face_base_fp32_v2_0_0` (34 MB), presumably the 5.8 model with "automatic emotion detection and procedural blinks" (S1). `GuiToRawControlsUtils::ConvertGuiToRawControls` (MetaHumanCoreTech, runtime) turns its GUI controls into the 251 raw `CTRL_expressions_*` curves, exactly as Epic's own real-time node does (S2).
- Licence: Epic plugin and content, UE EULA; free.
- Run time: prebuilt for Win64 game builds. Backends are `NNERuntimeORTCpu`, or `NNERuntimeORTDml` (Epic's Windows default; DirectML should run on AMD, but that is unproven here). A paid Fab plugin advertising "81 controls, 12 moods" appears to wrap this model and ships packaged demos (S9): indirect evidence it works packaged.
- Latency: reading the code, output trails input by the 80 ms lookahead. We hold the PCM before it is heard, so we can solve ahead and apply each frame at its audio time.
- Cost: unmeasured. One inference per 20 ms per speaker, on a worker thread.
- Effort: 1 to 2 days. Enable StreamingADA and NNERuntimeORT; add SpeechAnimationSolver, NNE, MetaHumanCoreTech and AnimGraphRuntime to Build.cs. The model loads by path, so add `/StreamingADA` to the directories always cooked.
- Risks: hidden, beta, undocumented; may change in 5.9. Hears sound, not words; untested on British voices.
- Pre-made wavs: same solver over raw PCM copies (cooked SoundWaves are compressed).

**2. Epic's documented routes.** The offline audio solve (module MetaHumanSpeech2Face) is editor-only (S3). The real-time "MetaHuman (Audio)" Live Link source (5.6+, with Blueprint calls added in 5.7) is a runtime module (S4, S5). But its API only opens input devices, its C++ is closed (S6), and Epic says it uses the GPU heavily (S4).

**3. Amplitude-driven jaw (the fallback).** Free, engine only: `UAudioComponent::OnAudioSingleEnvelopeValue`, or the loudness of each 20 ms of queued PCM. Drive `CTRL_expressions_jawOpen` (about 0 to 0.35), a little `mouthStretchL/R` and `mouthFunnelUL/UR/DL/DR` by loudness, and `mouthLipsTogetherUL/UR/DL/DR` on silence, smoothed over 50 to 80 ms. At a distance it reads as talking; close up it reads as "jaw flapping" (S10). Half a day; it stays as the safety net.

**4. Driving the face from C++.** RigLogic reads the face mesh's DNA and turns the `CTRL_expressions_*` curves into joints and shapes (S11). Build a native face anim instance, as PersonAnim.cpp already does for bodies, whose root is `FAnimNode_ModifyCurve` (`CurveMap`, `ApplyMode` WeightedMovingAverage), with values copied in at PreUpdate. RigLogic then runs in Epic's `ABP_Face_PostProcess`, or add the public `FAnimNode_RigLogic` to the proxy. Which of the two our faces use now is unchecked.

**5. Ruled out.**
- NVIDIA Audio2Face-3D: SDK and UE plugin (v2.5, UE 5.5/5.6) are MIT, but it needs an NVIDIA GPU with CUDA 12.8+ and TensorRT, and the models are under the NVIDIA Open Model License (S7, S8).
- OVR LipSync: Oculus SDK licence; end-of-life (S12).
- Rhubarb (MIT): whole files only, cartoon shapes (S13).
- Georgy Dev lip sync: paid (S9).
- NeuroSync: "MIT" plus a revenue clause; "not for production" (S14).

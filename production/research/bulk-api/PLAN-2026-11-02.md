# Bulk text work onto the API credit: the plan (2 November 2026)

His order of 2 November, n02-6-4-bulk-api: "Bulk text work moved off the allowance onto the API credit (rule 12): first the speech trials, then the checker's labels and the blind readers, later residents' routines and side stories; the token audit shows the allowance saved." Rule 12 (RULINGS.md, 1 November): a $200 monthly credit, gone at the month's end; the day's ceiling is what remains divided by the days left (about $20 a day to about 11 November, then about $6.50); the cheapest model that passes; batches where that works; each day's spend logged; the key never printed, copied or committed.

## Where things stand

- **The speech trials are on the credit already:** the in-game runs of 1 and 2 November ($0.99 and $1.51, production/api-spend.jsonl).
- **The rest of the credit goes unused:** about $2.50 of about $40 available on those two days.
- **The allowance's text work** (production/research/token-audit/READING-2026-11-02.md): reviewing by helpers is 14% and research by helpers 16%. Much of it is reading and judging text, which a scripted call can do.
- **No scripted bulk runner exists.** tools/talk_cost_sample.py and tools/first_token_sample.py already show the safe pattern: the key read from LEDGER's own file and never printed, refused under CI, a cap checked before each call. But their cap is the old $1 a day, set before rule 12.

## The plan

1. **A batch runner, tools/api_batch.py.**
   - A file of requests in (id, model, system, messages, maximum length); a file of answers out.
   - Plain web requests, as the project's other tools make them; the Python library is not installed, and installing it would be a download.
   - The Message Batches endpoint where an answer can wait (half price), single calls where it cannot.
   - The day's ceiling worked out from production/api-spend.jsonl and the month's credit, checked against each run's worst case before anything is sent; each run appended to production/api-spend.jsonl.
   - A dry mode that prices a file without a key.
   - Its own self-test.
2. **First use, the claim check's labels:** new labelled details for the claim-check bench, written by Haiku 5.5 and checked against the 238 details already labelled (the bench of 7 October) before any are kept.
3. **Second use, the blind readers:** text-only judgements now done by helpers in this session, such as reading lines for accent and period, and checking written text against canon and its sources. Each moves when a scripted reader agrees with the helpers' past verdicts on the same material (agreement measured, not assumed). Picture reviews stay with the session's reviewers.
4. **Later, residents' routines and side stories** (the next order's waiting list: n02-9-side-stories).
5. **Measure:** the next weekly token audit shows the allowance's reviewing and research share falling, beside the day's API spend.

# Study B: Silent Hill 2 from the game's own files, 6 November 2026

All facts read 6 November 2026 from C:\Games\Silent Hill 2\SHProto\Content\Paks (SHProto-Windows.pak/.ucas/.utoc). "Measured" = read from a file. "Estimate" = worked out from a measured size, marked as such. Nothing from the game is kept in LEDGER; only these numbers. Extracts (small config copies, lists) were written to F:\LedgerTools\aaa-study\study-b-sh2 and are deleted at the end of this task (see the last section).

**Corrected by its review (FILES-2026-11-06-REVIEW.md), 6 November.** The file list, config copies and class lists are deleted, so the file counts, sizes, config values and cloth, morph and body counts below were read once and have no surviving copy; the review could not re-check them, and the reader's "ERR" line means "none failed" may not cover exports. The Mafia mappings trial left no record. No mappings were found in the game or F:\LedgerTools; the rest of the PC was not searched. Virtual shadows off and "all lighting dynamic" were read from the project settings only, preset overrides unchecked. Bulk totals are taken as textures; other assets may hold bulk.

## Method and access

- The container is not encrypted: the .utoc flags byte is 9 (compressed, indexed; the encrypted bit is clear), and the .pak footer's encrypted flag is 0 (measured, file headers). No key was needed or used.
- The engine is Unreal 5.1: the string "Release-5.1" is in SHProto-Win64-Shipping.exe (measured).
- Method: the open-source CUE4Parse library that sits inside FModel.exe (cut out of that file's bundle; FModel's window not used) loaded from a small program run with the .NET 10 runtime on F:. Result: 112,493 files listed with sizes; text configs read; package headers (class of every export) read.
- Property data (the part with sizes of textures, triangle counts, bone counts) needs a mappings file for this exact build. None exists on this PC for Silent Hill 2. The Mafia mappings file was tried and fails (the mesh read back empty: no bones, no lods, no materials; textures read as 0x0), so every result below from that route is dropped. Only class names (from the package header) and file sizes are used.

## Clothes: how a character's clothes are built

Measured from the package headers (class of each export) in Game/Characters, 130 character packages read, none failed. The 130 were a selection, its rule unstated, so nothing below holds for every character.

- One skeletal mesh per character, clothes inside it (inferred, unverified: headers give classes, not geometry): the characters read have a single SkeletalMesh export (Maria: Meshes/Maria.uasset, 29,276,568 bytes; James: Mesh/JamesSunderland_2022_08_29.uasset, 52,500,119; Angela: Angela_rig.uasset, 26,049,138; Mary: Mary_SkeletalMesh.uasset). Garment textures are named per part, for example Maria's Top, bottom and Arms sets (TB/TN/TORM/TG/TGcloth). So the skeletal mesh count is 1 per character version, not one per garment. Variants are separate meshes (Maria_UpsideDown, Eddie with and without cap, Laura_Mesh and Laura_Skirt_Mesh).
- Simulated cloth: yes, Chaos cloth. Each such mesh package contains ClothingAssetCommon exports with the same number of ChaosClothConfig exports and one ChaosClothSharedSimConfig. Counts of cloth assets per mesh package: Maria 5; Maria_UpsideDown 1; Angela 4; James 8; Mary 3; Laura_Mesh 1; Laura_Skirt_Mesh 1 (a separate skirt mesh, plus a blueprint Laura_Mesh_With_Skirt with two skeletal mesh components); Nurse_OW 3; Nurse_OW_v2 3. Among the packages read, none found in: Eddie (both meshes), SickMary_Export, Nurse (original, v2, v3), Mannequin, BossMary, the dead-body meshes. Which garment each covers, and its use in play: unread.
- Separate cloth-sim physics assets exist: Maria_rig_clothSim_PhysicsAsset (3 body setups) and Mary_rig_clothSim_PhysicsAsset (3); extra "CTH" physics assets with 5 body setups for Maria, Mary, Angela, James. Main physics assets: Maria 20 bodies / 19 constraints; Angela 14 / 13; James 36 / 35; Eddie 19 / 18; Nurse 57 / 60 (counts of export classes).
- Morph targets: 762 to 791 per main character mesh read (Maria 765, Angela 773, James 766, Mary 762, Laura_Mesh 791, SickMary 764, Eddie 769 / 765). Mannequin has 2, BossMary 10.
- Hems and skirts: Chaos cloth assets (counts above) on the skirt-bearing meshes; the patch note "improved the deformation of Nurses' skirts" matches Nurse_OW having 3 cloth assets (inference). Which vertices are simulated versus skinned: unverified (needs property data).
- Materials: material instance counts in the character folders (names containing _MI or Material, measured): Maria 30; Angela 12; James 76. Per mesh slot count: unverified.
- Texture sizes (estimate from .ubulk sizes in the file list; these sums stop at the 128 mip, not a full chain, which for the first would be 22,369,621): 22,364,160 bytes = 4096x4096 at 1 byte per pixel (BC7 or BC5) with mips; 11,182,080 = 4096x4096 at half a byte (BC1/BC4) or 4096x2048 at 1 byte, both exact; 5,586,944 = 2048x2048 at 1 byte; 2,793,472 = 2048x2048 at half a byte; 1,392,640 = 1024x1024 at 1 byte. Maria: 68 bulk files; 15 at 22,364,160; 18 at 11,182,080; 11 at 5,586,944; 4 at 2,793,472; 8 at 1,392,640; the rest smaller; 88 texture packages; bulk total 625,623,040 bytes. Angela: 39 bulk files (9 at 22,364,160); bulk 346,570,752. James: 116 bulk files (35 at 22,364,160); 169 texture packages; bulk 1,335,058,432. Laura 345,194,496 bytes; Mary 295,026,688; Eddie 270,548,992; Nurse_OW 150,937,600. The pixel format is not read, so the 1-byte and half-byte readings are two possible sizes for one file size: unverified.
- Triangle counts per mesh and LOD, bone counts, section counts, skin-weight limits, vertex counts: NOT reached. They sit behind the property block, which needs this build's mappings file. Unreached, not evidence.

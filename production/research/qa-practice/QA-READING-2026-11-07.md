## A. Automatic testing

**1. Unreal Automation and Gauntlet**
- Automation tests run four ways: in the editor (Session Frontend), against other connected instances, from Unreal Frontend as a standalone client, and from the command line with `-ExecCmds="Automation RunTest A+B;Quit"`. `-ReportExportPath` writes JSON plus HTML; `-ResumeRunTest` resumes from the first test not yet run, marking one in progress as failed. https://dev.epicgames.com/documentation/en-us/unreal-engine/run-automation-tests-in-unreal-engine
- Test categories named by Epic: Unit, Feature, Smoke (meant to finish within 1 second), Content Stress (load all maps, compile all Blueprints), Screenshot Comparison. Ways to write tests: Automation Spec, Automation Driver (simulated user input), Functional Testing (Blueprint, level tests), CQTest, editor tests in Blueprint or Python. Epic's guidance: tests must not assume state and must clean up their files. https://dev.epicgames.com/documentation/en-us/unreal-engine/automation-test-framework-in-unreal-engine
- Gauntlet runs "sessions" (all processes a game needs, such as clients plus a server) and needs no game-side framework; an optional plugin gives a TestController to steer a game instance. https://dev.epicgames.com/documentation/en-us/unreal-engine/gauntlet-automation-framework-in-unreal-engine
- Driving a build: `RunUAT RunUnreal` with `-test`, `-project`, `-build`, `-platform`, `-device`. Built-in tests: UE.BootTest, UE.EditorAutomation, UE.TargetAutomation, UE.Networking, UE.ErrorTest, UE.PLMTest. A test is a C# class (UnrealTestNode) declaring roles, command-line parameters and a MaxDuration; a test can end on a log message. Gauntlet reports a summary when the run ends without errors and watches for crashes, asserts and fatal errors; `-ResumeOnCriticalFailure` allows up to three resumes. Consoles and phones need custom device classes. https://dev.epicgames.com/documentation/en-us/unreal-engine/running-gauntlet-tests-in-unreal-engine

**2. Bots in studio production**
- Ubisoft Massive, The Division (blog by Tommy Thompson, 4 Mar 2020, interview with Philip Dunstan, lead AI programmer; not a GDC text). Server bots: teleport, god mode, disconnect/reconnect, form groups; stress the servers (built for about 1,000 players); their metrics matched real players'. Client bots: follow human rules, run on PC and consoles, made for the Underground DLC whose missions had hundreds or thousands of variants; ran hundreds of permutations over a weekend; in Division 2 designers added invisible test markup; nightly mission tests with a goal of zero failures in three error categories; consoles log FPS and memory nightly or continuously. Stated limits: they follow a hand-placed golden path, need scripted setup for doors and similar, and miss areas off the path; human testers are still needed. https://www.gamedeveloper.com/design/the-secret-ai-testers-inside-tom-clancy-s-the-division
- EA SEED, Bergdahl et al. (CoG 2020, arXiv 2103.15819), read via ar5iv digest (the arXiv PDF came back as binary): reinforcement-learning agents in four sandbox maps, not whole games; one agent walked through a wall lacking collision, which a scripted navmesh agent never found; timeouts marked all five stuck areas; training took 50 to 1,000 million frames; the setup was one server with four client machines. No money cost reported. Authors present RL as a complement to scripted tests. Research, not a stated production rollout. https://ar5iv.labs.arxiv.org/html/2103.15819
- EA, Gillberg et al. 2023, Battlefield 2042 and Dead Space: an experimental RL system added to an existing scripted-bot test solution; only the abstract was read, no results on the page. https://arxiv.org/abs/2307.11105v1
- NetEase / Zhejiang, TITAN (arXiv 2509.22170): GPT-4o at temperature 0 plays an online RPG from text-abstracted state; screenshots are used only when progress stalls and as bug-report evidence. Task completion 95% against humans 100%; 4 previously unknown bugs; false-alarm rate 30%; "deployed in 8 QA pipelines" with no detail; no token or money cost reported; the digest flagged internal inconsistencies in the bug-count figures. Two games, one model. https://arxiv.org/html/2509.22170v1
- Not reached for lack of a primary page: King's papers (only search listing: Gudmundsson et al. 2018, a learned human-like player to predict level difficulty), Microsoft Research's game-testing page, Unity's own bot practice, Ubisoft La Forge's testing talk (GDC Vault, likely paywalled).

**3. Picture-against-picture checks**
- Unreal Screenshot Comparison: a verified screenshot is the baseline; a mismatch fails. Tolerance presets Zero to High, or custom: per-channel RGBA, brightness limits, maximum local error (small regions), maximum global error, ignore anti-aliasing, ignore colours. Results go to Saved/Automation/Comparisons, with a slider view of old against new; "Replace" sets a new baseline, "Add As Alternative" keeps a second valid image for different hardware. Captured by a Functional Screenshot Test actor. Reports are not cleared automatically. https://dev.epicgames.com/documentation/en-us/unreal-engine/screenshot-comparison-tool-in-unreal-engine
- Unity Graphics Test Framework: only found by search; the class pages were not opened. Search listing says default is exact match, with tolerance settings for pixel difference and count of wrong pixels; unverified.

**4. Per-build performance**
- Unity Performance Testing Extension: measures profiler markers, frames and custom metrics in the editor and built players, with median, min, max, average, standard deviation, sample count; builds a development player; advises one quality level and vsync off; stores build and player settings as metadata. The page does not describe baseline comparison. https://docs.unity3d.com/Packages/com.unity.test-framework.performance@2.8/manual/index.html
- Epic's Automated Performance Testing plugin (forum reply by Epic staff, undated in the digest): ties BuildGraph, UAT, Gauntlet, CSV Profiler with PerfReportTool, and Unreal Insights; runs yield CSV and Insights traces as Gauntlet artifacts; GPU and CPU stats; ready-made controllers are Static Camera and Sequencer, the replay controller needs a replicated game; the glue is called experimental; result display still open. https://forums.unrealengine.com/t/automated-performance-testing-plugin-guidance/2666136
- Ubisoft Massive (above): wandering bots log FPS and memory nightly on consoles. A Fab plugin (PerfGuard) advertises baseline thresholds; unverified, vendor claim only.

**5. Fault database**
- One blog template (Leszek Gorniak, Game Developer, 22 Jun 2018): ten fields: title, category, severity/priority, steps to reproduce, current result, expected result, affected version, reproducibility, platform, attachments (screenshot, video, log). Severity runs Minor to Blocker; priority is set separately. https://gamedeveloper.com/design/how-to-report-bugs
- Secondary guidance (search listing only, not opened, so unverified): four-level Minor/Major/Critical/Blocker with Low/Normal/High/Urgent priority; five-level S1 to S5 in general QA; blockers tied to crashes, lost saves, blocked progress. No standard exists; sources say to define levels per game.
- The tester's own scale in this project: `note SEVERITY` from 5 unplayable to 1 cosmetic (packaged-walk SKILL.md, read 7 Nov).

**6. Agents that play from the screen**
- Cradle (arXiv 2403.03186, abstract only): screenshots in, keyboard and mouse out, no game API. Reported: 40-minute missions in Red Dead Redemption 2, a 1,000-person city in Cities: Skylines, farming in Stardew Valley, trading in Dealer's Life 2 (max weekly profit 87%). Abstract lists no failure modes. https://arxiv.org/abs/2403.03186
- GBQA benchmark (arXiv 2604.02648, abstract only): 30 games, 124 human-verified bugs; best model (Claude-4.6-Opus, thinking) found 48.39%; input format not stated in the abstract. https://arxiv.org/abs/2604.02648
- Anthropic computer-use docs: each screenshot about 1,000 to 1,800 input tokens; loops accumulate; resize screenshots (1280x720 suggested, nothing above 1920x1080); small targets and downscaling cause missed clicks; set an iteration cap; the tool is not aimed at real-time play (the docs' text gives no game guidance; read as digest, the last 28,540 characters unread). https://platform.claude.com/docs/en/build-with-claude/computer-use
- No source found giving a money cost per game hour. TITAN and Cradle give none.

**9. Exploratory testing.** Session-based test management (Wikipedia, citing James and Jon Bach, HP origin): charter set before a session; one to two hours uninterrupted; report holds charter and area, notes on how, bugs and open questions, files used, time split charter versus new opportunities and testing versus bug investigation versus setup; debrief with PROOF (Past, Results, Obstacles, Outlook, Feelings). https://en.wikipedia.org/wiki/Session-based_testing. The Bach paper on satisfice.com returned only its abstract: unreached in full.

**10. Checklist and certification.** Microsoft Xbox, XR-003 (https://learn.microsoft.com/en-us/gaming/gdk/_content/gc/policies/xr/xr003, first 100,000 of 173,331 characters read): the tester signs in, navigates every menu and sub-menu, completes every mode in every supported language, tests offline, online and split-screen, and watches for crashes, blocked progress, dead-end navigation, options reset after relaunch, unreadable localised text, frame-rate problems. Save compatibility: play, save, reload; install the update; old save loads; new save on the old build must load, show an update message, or be hidden. Headset unplug/replug and suspend/sleep/hibernate steps. The only log named is Submission Validator's, supplied with the submission. Top failing cases (same site, version 3.0, 6 Aug 2026; https://learn.microsoft.com/gaming/gdk/docs/store/policies/console/console-topfailingtestcases): title stability 38% of console failures and 34% of PC; title integrity 14% and 4%; guidance includes random input on all screens, rapid enter-and-back-out of menus, five PC resolutions (1366x768, 1440x900, 1080p, 1440p, 4K) in window and full screen, installing from the store rather than side-loading. Sony and Nintendo requirements: only blog descriptions found; unreached.

# Why Unreal's cache went back to C: after its move to F (research note, 30 September 2026)

The problem, as given to a separate helper (about 30 minutes, dated sources): Unreal's cache server (Zen) kept storing its data in `%LOCALAPPDATA%\UnrealEngine\Common\Zen\Data` on C: (5.8 GB written that morning), `F:\LedgerTools\zen\Data` stayed empty, although the user-wide settings file named F:. Kept here as it reported, with its evidence.

## Cause

- The settings file `%LOCALAPPDATA%\Unreal Engine\Engine\Config\UserEngine.ini` exists on disk only inside the Claude desktop app's private copy of AppData (`...\AppData\Local\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\...`). Claude's Windows app is an MSIX package, and Windows redirects a packaged app's writes to AppData there (Microsoft Learn, "Flexible virtualization", updated 28 January 2026). Programs started from Claude see that copy; programs started outside it do not.
- The build machine's runner was started on 22 September from a plain command prompt, outside Claude. Its Unreal runs on 30 September (material step, cook, UnrealPak, 09:43 to 09:50) logged "Found Zen config default=C:", Epic's 14-day arguments and a writable old file cache. Unreal runs started from Claude (09:15 to 09:33) logged "default=F:", the capped arguments and a delete-only old cache.
- A path set as `[Zen.AutoLaunch] DataPath` is Unreal's "default", and when the default changes Unreal migrates to the new one and deletes the old location (Engine source on this PC, ZenServerInterface.cpp lines 4241 to 4261; the last one used is kept as InUseDefaultDataPath in `%LOCALAPPDATA%\UnrealEngine\5.8\Saved\Config\WindowsEditor\EditorSettings.ini`; Epic staff on the forum, 12 June 2026, thread 2735146: intended). So a local run at 09:15 deleted C:'s store, and the runner at 09:43 deleted F:'s. The two sides also stop each other's cache server on port 8558 when their settings differ.

## Where the path comes from in UE 5.8, highest first

`-ZenDataPath=` on the command line; the environment variable `UE-ZenSubprocessDataPath`; the registry `HKCU\Software\Epic Games\Zen`, value `DataPath`; the environment variable `UE-ZenDataPath`; the local cache path plus `\Zen` (from `UE-LocalDataCachePath`, the GlobalDataCachePath registry key, `-LocalDataCachePath=` or the editor's LocalDerivedDataCache setting); then `[Zen.AutoLaunch] DataPath` in the Engine config (ZenServerInterface.cpp, DetermineDataPath, lines 985 to 1105). The user-wide file Unreal reads is `%LOCALAPPDATA%\Unreal Engine\Engine\Config\UserEngine.ini`, then Documents' copy, then the project's (ConfigHierarchy.h). None of the higher ones was set on this PC.

The old file cache: installed builds use the "Installed" graph, whose old file cache is `InstalledLocal`; `DeleteOnly=true` is the right key (FileSystemCacheStore.cpp line 3085).

## What LEDGER did (30 September)

- The build machine's workflow installs `tools/ue/UserEngine.ini` into the real `%LOCALAPPDATA%` before any Unreal step, since the runner runs outside Claude: both sides then read the same default (F:), and Unreal's own migration clears the copy on C: once.
- Not done: the registry value the helper suggested as a safeguard (it outranks every file and is not a "default", so nothing deletes itself); a registry write from inside Claude is likely virtualized too, and the file alone makes both sides agree.
- Also inside Claude's private copy: `%LOCALAPPDATA%\LEDGER`. The game Jafar starts himself reads the real folder, where his live-talk key is; nothing here reads the key.

# Capping Unreal's own cache (28 September 2026)

The problem (Jafar, 28 September): Unreal's shared cache on C: (UnrealEngine/Common in the user's local app data) grows by gigabytes with every MetaHuman build and game run, and helped take C: under 60 GB. Cap it in Unreal's own settings so it trims itself. Researched by a separate helper against the engine's own files on this PC; applied and checked by the builder.

## What was found

- The folder held 26.8 GB: the old file cache (DerivedDataCache, 13.9 GB) and the Zen store (Zen/Data, 12.8 GB). UE 5.8's installed-build graph (BaseEngine.ini [DerivedDataCacheGraphs] `InstalledDerivedDataBackendGraph=(..., ZenLocal, Local=InstalledLocal, ...)`) writes both, so the same data was kept twice (ue-probe logs: `ZenLocal: ... Status: OK!` and `Local: Using data cache path ...: Writable`).
- The only built-in trims were by age (Zen 14 days, `--gc-cache-duration-seconds 1209600`; the file cache 34 days) and a low-disk trigger at 2 GB free. Zen lives only while an editor runs, so its age trim rarely ran.
- Zen has a size cap, off by default: `--gc-disksize-softlimit <bytes>` (zenserver.exe 5.8.13 --help: "Garbage collection disk usage soft limit. Default set to 0 (Off)"). It is passed through `[Zen.AutoLaunch] ExtraArgs`. Not in an Epic document found; the help text and a throwaway test server confirmed it.
- The file cache has no size option (FileSystemCacheStore.cpp parses age, DeleteOnly, Clean and Flush). Epic documents that with Zen the old cache belongs in delete-only mode. Source: https://dev.epicgames.com/documentation/unreal-engine/using-derived-data-cache-in-unreal-engine (UE 5.8, undated, read 28 September 2026); forum answer on Zen GC, 19 December 2025: https://forums.unrealengine.com/t/zenserver-local-ddc-and-controlling-gc/2693062
- The setting belongs in the user-wide file `%LOCALAPPDATA%/Unreal Engine/Engine/Config/UserEngine.ini` (ConfigHierarchy.h: `{USERSETTINGS}Unreal Engine/Engine/Config/User{TYPE}.ini`; Local, not Roaming, app data on Windows). One project alone would make the two projects restart each other's Zen with different arguments. The build machine runs as the same user, so it is covered.

## What was done

`UserEngine.ini` written (a copy is in tools/ue/UserEngine.ini): Epic's own ExtraArgs with the age limit at 7 days and `--gc-disksize-softlimit 21474836480` (20 GiB) added; `InstalledLocal=(Type=FileSystem, DeleteOnly=true, UnusedFileAge=7, ...)`. Checked on this PC the same day: zenserver.log reads "12.5G used, 20G soft limit" and the editor log reads "Local: Using data cache path ...: DeleteOnly". No rebuild; anything evicted is rebuilt when next needed. Caveat: Zen checks only while an editor or game runs.

## What the test has already shown (method, not setting)

1. Headless per-asset painting works: bake, mask and engine export from a script, same pixels twice, no window. Its masks must be baked from the high drape, never the game mesh (blocky).
2. Generator levels are traps: TextureCraft's edge wear shows nothing at its default 0.5; narrow mouldings read as all edge at any level, so the share is set by a levels cut measured inside the UV islands, never over the whole picture.
3. MaterialCraft 0.3 ships no brick, fabric or wood: every tile is built from primitives (true-size SVG patterns plus outside noise). Warp strength is the other trap (0.05 to 0.08 reads as worn arrises; 0.2 chews edges; 3 scrambles).
4. A test row must be checked map by map before filming: a failed bake can be a flat file that imports without error. Add to the garment skill: the import's report should name any map with no variation.

## Missing or broken in each tool (so far)

- MaterialCraft: no ready patterns or noise in 0.3 (built ourselves); its MCP schema issue 146 untested here. Fixable by its makers; we work round it with SVG.
- TextureCraft: no direction or geometry weighting that tamed the cornice (thin-areas mask did not); channel order read from its preset, not its docs. Open issues 365 and 375 (quads, offset UVs) not met yet.
- Ours: no switch to show a candidate street surface beside the shipped one in the packaged game; the brick's tone map is bound to one scan.

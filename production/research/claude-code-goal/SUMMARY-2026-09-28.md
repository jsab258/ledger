# /goal, the old stop hook, and usage limits (28 September 2026)

The question (Jafar, 28 September): does this version of Claude Code have /goal, and does a session wait and continue on its own when a usage limit resets, with no click from him? Researched by a separate helper (Claude Code's own documentation and changelog); checked against this PC.

## What was found

- **/goal exists** from Claude Code 2.1.139 (May 2026). This PC runs 2.1.272 (`claude --version`, 28 September). `/goal <condition>` keeps the session working across turns until the condition is met, judged impossible, or cleared; it survives reconnection. Source: https://code.claude.com/docs/en/goal.md (read 28 September 2026); release note https://x.com/ClaudeCodeLog/status/2053913625983692979 (May 2026).
- **/goal is itself a session-scoped Stop hook** ("a wrapper around a session-scoped prompt-based Stop hook"; both fire after every turn). The documentation does not call a settings Stop hook a conflict, but two deciders on the same event can disagree; Jafar's ruling removes ours (.claude/settings.json no longer has hooks; the sitting-continue.sh script and tools/sitting-clock.py are gone).
- **Usage limits**: from 2.1.234, an interactive session signed in with a claude.ai subscription waits at a usage limit and resumes when the window resets ("Usage limit reached · continuing automatically at HH:MM"). It is on by default and toggled in /config ("Continue automatically at usage limit"); an active /goal stays active across the pause. Source: the goal page above, section on pauses; changelog https://code.claude.com/docs/en/changelog (read 28 September 2026). This PC's ~/.claude.json holds no override, so the default (on) applies.
- **Permissions**: an unattended goal needs a permission mode that does not stop for approval each turn; this session runs in auto mode.

## Documented or inferred

Documented: /goal and its version; the pause-and-resume at usage limits and its version. Inferred: that the desktop app's Code tab behaves as the documented interactive session (it runs the same Claude Code); not yet seen happening on this PC.

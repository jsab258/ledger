## 1. What Unreal 5.8 ships

**The framework.**
- The Data Validation plugin is on by default (Plugins/Editor/DataValidation/DataValidation.uplugin).
- UEditorValidatorSubsystem runs each asset's own IsDataValid, then every registered validator (Public/EditorValidatorSubsystem.h, class comment).
- A validator subclasses UEditorValidatorBase (Public/EditorValidatorBase.h). A script validator answers K2_CanValidate, K2_CanValidateAsset (false by default) and K2_ValidateLoadedAsset, which must call AssetPasses or AssetFails; "not validated" trips an ensure (Private/EditorValidatorBase.cpp lines 27 to 31, 87 to 100). In 5.8 Python: k2_can_validate_asset, k2_validate_loaded_asset (web-sources.md 4).
- Python validators must register themselves with add_validator (EditorValidatorBase.h line 24); the native scan skips classes outside /Script (EditorValidatorSubsystem.cpp line 389).
- Python start-up scripts run before any commandlet's main, so that Python validators can run there, says Epic's comment (PythonScriptPlugin.cpp lines 1381 to 1389, Plugins/Experimental). An unanswered forum thread reports failure. The method registers its validators in its own script, so this does not matter.
- Validate on save is on (Public/DataValidationSettings.h line 26).

**What ships** (every UEditorValidatorBase subclass under Engine/Source and Engine/Plugins):
- **On by default:** PackageFileValidator (the file on disk is not corrupt); localisation; action utilities; Enhanced Input's; two changelist validators for source control.
- **EditorValidator_Material** (each material compiles) is registered but **checks nothing here**. It needs a platform list, and no ini on this PC sets one: not the engine's, ue-probe's or mh-assemble's. It also skips save and commandlet runs unless Editor.EnableMaterialAssetValidator is set (Private/EditorValidator_Material.cpp lines 18 to 21 and 85 to 94).
- **Off:** MaterialValidation (beta; permutation limits); AssetReferenceRestrictions (which folders may reference which); the Mutable and Game Features validators.

**The engine's own data checks (IsDataValid).**
- Static mesh: no source model, an empty LOD, a bad Nanite source, a minimum LOD out of range (Runtime/Engine/Private/StaticMesh.cpp line 5491). Skeletal mesh: no or incompatible skeleton, broken bones (SkeletalMesh.cpp 1754). Physics bodies: no shape, or no mass when simulated (PhysicsEngine/BodySetup.cpp 1656). Levels check their actors (World.cpp 1053).
- Messages logged while loading each asset are captured: load errors fail the asset; load warnings, such as a missing reference logged as a warning, stay warnings (EditorValidatorSubsystem.cpp lines 916 to 936). Missing parts therefore need rule 8.

**Not built in:** any rule for triangle counts, texture sizes, names, LOD counts, static-mesh collision or Nanite. Epic's page lists naming and budgets as uses, for projects to write (web-sources.md 1).

**The commandlet.**
- The line is `UnrealEditor-Cmd.exe <project>.uproject -run=DataValidation`. The source reads only `-AssetType=<class>`, `-IncludeOnlyOnDiskAssets` and `-includeengine` (Private/DataValidationCommandlet.cpp lines 148 to 150).
- **It cannot take a folder:** it validates every asset outside /Engine (lines 155 to 205).
- **Its exit code is no verdict.** Its main returns 0 when assets fail, and 2 only when it cannot run (lines 37 and 229). The process then exits 1 if any error at all was logged (Runtime/Launch/Private/LaunchEngineLoop.cpp lines 4217 to 4223).
- The verdict is in the log: "Data validation SUCCEEDED/FAILED" and the "Files Checked, Passed, Failed" counts (EditorValidatorSubsystem.cpp lines 1119 to 1135), which the message log copies to the output log (Runtime/Core/Private/Logging/MessageLog.cpp lines 120 and 271).
- **The route for one folder** is the subsystem's validate_assets_with_settings from Python: load the assets (true in the header, line 176, false on the 5.8 Python page, so set it), collect per-asset details (line 168), usecase SCRIPT.

**In the editor:** Validate Assets (also in Folder) and Tools > Validate Data. Asset Audit shows sizes and chunks, no rules (web-sources.md 1).

**Engine calls a rule can use (headers read).**
- **Static mesh:** get_num_triangles, get_num_lods (Classes/Engine/StaticMesh.h lines 2153, 2177); StaticMeshEditorSubsystem (Editor/StaticMeshEditor/Public/StaticMeshEditorSubsystem.h): collision counts (259, 276), complexity (267), materials (486), Nanite (217).
- **Skeletal mesh:** SkeletalMeshEditorSubsystem get_lod_count, get_num_verts, regenerate_lod (Editor/SkeletalMeshEditor/Public/SkeletalMeshEditorSubsystem.h lines 252, 66, 57). No triangle count is exposed; Geometry Script's CopyMeshFromSkeletalMesh and GetNumTriangleIDs give one (Plugins/Runtime/GeometryScripting, MeshAssetFunctions.h line 410, MeshQueryFunctions.h line 90), with the plugin added by -EnablePlugins; untested.
- **Texture:** its size (Texture2D.h lines 360 and 366); its source colour range, which finds a flat placeholder (Texture.h line 1658); compression and sRGB as properties.
- **Freshness:** meshes and textures keep their import file's name, time and MD5 in a hidden registry tag, comparable with the export file on F: (StaticMesh.cpp line 6230, SkeletalMesh.cpp 4631, Texture.cpp 1482; EditorFramework/AssetImportData.cpp line 49).

## Method

**Build tools/ue/asset_checks.py** in nanite_audit.py's pattern:
- The rules are Python validators (subclasses of unreal.EditorValidatorBase, registered with add_validator).
- A runner takes the piece's folders from the asset registry and calls validate_assets_with_settings as above, so Epic's checks and the engine's IsDataValid run in the same pass.
- Each project's DefaultEditor.ini lists one material validation platform (this PC's, at High), so Epic's material check works; a planted grid material proves it.
- A `--selftest` holds planted cases and runs without Unreal.

**One home for the thresholds.**
- They live in production/specs/asset-budgets.json, with a catalogue line. It maps exact folders to kinds (the garments' folder before the MetaHumans' exemption), and each kind to its numbers and sources. 4-BUDGETS.md stays the research behind it.
- A changed number needs a DECISIONS line and a spec edit, never a code edit.
- A set-aside fault goes on the spec's waiver list with its DECISIONS and FINDINGS lines, so a known shortfall fails nothing alone (CLAUDE.md, "The gate").

**The rules.** Errors fail the piece; warnings are listed.

| # | Rule | Threshold | Source |
|---|---|---|---|
| 1 | Epic's validators and IsDataValid | any error | section 1 |
| 2 | Full-detail triangles by kind | below the table; a warning above 90% (our choice) | Study 6; 4-BUDGETS 4.7 |
| 3 | Levels of detail | count by kind: principal's garments 4, crowd outfit 3, accessory 2, static kinds 4-BUDGETS's 2 to 4. Each about half the last: at most 60% (our tolerance, a DECISIONS line). MetaHuman bodies and Epic assets exempt | Study 6 (47/25/9%); 4-BUDGETS 4.7; DECISIONS 3 Oct |
| 4 | Nanite off | every static mesh under /Game/Ledger (nanite_audit folded in) | DECISIONS 3 Oct |
| 5 | Texture size | See below the table | Epic's textures page; Studies 5 and 6; 4-BUDGETS |
| 6 | Texture role | normal: normal-map compression, and its SourceCompression tag not JPEG (Texture.cpp 1485); packed: mask compression, sRGB off | Rita's front 30; import_garments.py 65 to 68 |
| 7 | Placeholders | no empty slot, default or grid material, one-colour texture, or non-glass material sampling no texture (unless listed); every material compiles | jacket's first build; office WEAR 62, 63 |
| 8 | Missing parts, freshness | every part in the piece's spec exists (the office's 18); each import MD5 equals its export file's | lamp 7; office WEAR 95; StaticMesh.cpp 6230 |
| 9 | See-through only where meant | translucent or transmissive only on slots named glass, or listed | chandler 32; ironmonger 59; tea rooms 39, 59 |
| 10 | Names | Epic's prefix for the class (SK_ or SKM_ for skeletal meshes); letters, digits and underscores; one case per prefix; in the gated piece's folders. MetaHuman, Fab and Epic imports exempt | Study 13; Epic; Allar |
| 11 | Collision | by kind: modules simple boxes; small prop none or one box; medium and large props simple, at most 10 hulls; car at most 6; none on displays, garments, signs, decals, unentered rooms; never complex-as-simple | 4-BUDGETS 4.7; Epic |

The caps for rule 2, in triangles at full detail:
- **Garments (Study 6):** jacket 22,000; jumper 20,000; trousers 10,000; shoes 6,000.
- **4-BUDGETS 4.7:** crowd outfit 8,000; accessory 4,000; building module 8,000; frontage 150,000; real room 100,000; display 60,000; props 1,500, 5,000 and 15,000 (small, medium, large); car 40,000.

The sizes for rule 5:
- Each side a power of two, none over 4096 (the trim sheets are 4096 × 2048).
- Principal's garment 2048; crowd garment and shoes 1024; hats and accessories 512.
- Props: small 512, medium 1024, large and display 2048.

The SKM_ prefix that the garment import already uses is settled within rule 10, with a DECISIONS line.

**Where it runs.**
1. **At the end of every import, in the same session:** import_garments, import_shop_rooms, import_street and import_prop_meshes call it for the folders they wrote. No extra editor launch, so no new clash with the build machine.
2. **On its own**, only while the build machine is idle, without -nullrhi (the material check compiles shaders; untested): `UnrealEditor-Cmd.exe <full path>\LedgerProbe.uproject -run=pythonscript -script=<full path>\asset_checks.py -EnablePlugins=PythonScriptPlugin -unattended -nopause -nosplash -stdout`, with LEDGER_CHECK_PIECE set.
3. **Before any reviewer:** each gate record opens with the check's line, same day, newer than the import. A FAIL stops the photographs. Reviewer briefs list what the machine settled, so reviewers judge only the look.
4. **In ci-checks, without the editor:** asset-checks-selftest; asset-checks-fresh (every piece's report has no unwaived error and unchanged input MD5s, as import_glass_bake.py --check-fresh does); source checks on export files (image sizes, powers of two).
5. **Nightly on the build machine:** all of /Game/Ledger, as a list that blocks nothing; each finding becomes a list item.

**How the report is read.**
- One line is appended to ue-material.txt, for example:

  `assetChecks=FAIL piece=tom-jacket assets=7 errors=1 warnings=0 first=lods:SKM_TomZipJacket:1/4`
- production/asset-checks/<piece>.json holds each asset, rule, value, limit and source.
- The session reads the line it just wrote, never the exit code, which is no verdict (section 1).

**After.**
- Apply gate-count.md's rule unchanged to every gate from the first run, for two weeks (to 11 November) or ten pieces, whichever is later.
- Report by kind (fronts, rooms, garments): rounds to first full pass, rounds and reviews per piece (median, mean), FAILs, machine faults still reaching a reviewer (covered classes are misses, ending as a fix or a rule), the check's catches before photographs, its time per run (tools/timelog.py). Few, mixed numbers: an observation, not proof.

**Not covered: the 21 placement and data faults, and facets.** A second step could measure the assembled piece against its spec: parts through each other or floating (Geometry Script's IsIntersectingMesh and FindNearestPointOnMesh, MeshComparisonFunctions.h line 146, MeshSpatialFunctions.h line 113), and rays from the gate cameras through joints. About 8 to 10 hours more, outside D13: a scope question for him.

**Hours: about 15**, plus 1 for a fresh review of the rules against their sources: runner and report 3; spec and records 1; triangles and levels 2; textures 1.5; placeholders and freshness 2; names 0.5; collision 1; planted-fault acceptance 2; wiring 1; first use 1.

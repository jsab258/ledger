## 1. The method that worked

**A pass is the player's game.** A piece passes only in the packaged build a player launches. Read the run's own logged command line: every switch is the player's, watch-only, or a test switch, and any test or unclassified switch fails the pass ("A pass must be the player's game (8 November 2026)"; tools/launch_line_check.py). The gate rehearsal two days before the phase exit found pieces that had "passed" only behind test switches ("Rehearsing a gate before it counts (7 Nov)"; production/audits/phase1-exit/REHEARSAL-2026-11-07-*.md). The game must say in its own log which path it took, and the build machine reads that line ("27 Oct 2026, a feature that only ever ran in the editor").

**Ship what is read at run time.** Content too big for the repository reaches the build machine only by an explicit copy step, and content loaded by name needs an always-cook rule; list both in the same change as the feature ("27 Oct 2026, a feature that only ever ran in the editor"; production/previews/tom-metahuman-packaged-2026-10-27.jpg). A check now fails the build when code names a data file the staging list leaves out ("A photographed tiling texture ... (3 November 2026)"). Garments: the shipped mesh must exist and be no older than its source or any side-project copy ("Asset checks widened to every folder that ships (8 Nov 2026)").

**Fresh reviewers, one view each, the last good picture beside.** 18 of 20 planted faults were caught alone and 20 of 20 beside the last good picture; a bundle of about ninety pictures hid a black block ("What came before 13 October", PROVEN and FAILED, The build and the gate; production/audits/reviewer-test/REPORT.md). Give each reviewer the true "before" (a picture from a failed try misled two reviewers: "26 Oct 2026, a quality setting raised only while the player is inside one room"), brief from the picture, not the plan ("30 Oct 2026, one shop front's weathering"), give the reviewer the measure, not the conclusion ("27 Oct 2026, a garment's rib cuffs"), and send a disputed reading back to the same reviewer with evidence rather than overruling ("23 Oct 2026, item 5: delivered fronts fitted under a lower eave"). A view never reviewed before gets a full fault hunt ("26 Oct 2026, a room's second wear pass").

**Phase exits by one reviewer per exit.** Give each the requirement word for word and where the outputs are, never the maker's verdict; a verdict per clause with the deciding file; recompute numbers from raw captures. All four phase-1 exits failed on 22 October, and the maker's own records were wrong in four places ("22 Oct 2026, item 9: a production phase's exit checked by one independent reviewer per exit"; production/audits/phase1-exit/CLOSE-2026-10-22.md).

**Golden rows between the reference simulation and its engine port.**
- A golden table from the reference code read by the port: 57,913 checks, no failure, and 650,000 random runs with no difference ("What came before 13 October", PROVEN, The simulation; production/audits/sweep-2026-10-05/port-vs-core.md).
- Rules that lived only in the port get a home in the reference code: write the test there first and watch it fail, move the body word for word, emit rows across the rule's edges, plant one-line breaks to prove the rows bite ("26 Oct 2026, a rule that lived only in the engine port"; "28 Oct 2026, a rule that lived only in the port given its home").
- Every planted break no test noticed was made to fail rows (eight of nine; the ninth dead code, pinned) ("28 Oct 2026, every one-line break the tests missed made to fail them").
- Audit the checker itself: no row silently dropped, and a verdict line with its denominator ("28 Oct 2026, a check's own holes closed").
- Drive rows from the real data files over every hour; a list-valued rule gets one row per item plus a count row, each number in its own field ("27 Oct 2026, an engine port's geography given its home").
- The shipped load path calls the port's pinned gate functions on its own file format before touching state ("Two engines, one rule for refusing a save (3 November 2026)").
- A rule set ported unwired, rows shown failing first, a seeded random draw carried over exactly (the unheaded 6 Nov entry "Porting one simulation rule set to the engine's language, unwired").

**Frame time: measure the shipped build to each cause.** On a scripted walk with the real background load, report the worst frame and the count over the bar, find where and when each slow frame falls, break it down with the game's named timers, then a full trace; fix the cause and re-measure the whole matrix after each fix; stamp baked data with hashes of its sources ("21 Oct 2026, item 6: a packaged game's worst frame on a walk"; production/research/pre-production/p1-packaged/runs.jsonl). Find a cost by switching one thing off in the packaged copy's data before writing code; re-measure every condition after each new piece ("23 to 24 Oct 2026, frame headroom"; production/research/frame-headroom/FINDINGS-2026-10-23.md). Count a rare fault before asking for another try: a one-in-25 fault needs about 75 repeats to show a fix ("The same stutter, its result (6 Nov)"; production/research/frame-headroom/STUTTER-2026-11-06-DIAGNOSIS.md).

**The automated tester.** A tester that steers by holding keys carries a model of the character's pace; when movement changes, measure the new pace and coast from its own path log; let the game log which movement it runs ("27 Oct 2026, a scripted tester's steering retuned"; production/playtest/ai-tester/2026-10-27-1926). Read every picture it takes for faults outside its stages. A stage reaches its target time of day, not the first moment inside a wide window ("A tester that kept arriving late", 5 Nov). Film walks on a fixed time step with a camera held still beside the walker ("A side-on film of a walk at full rate (8 November 2026)"). Walk the player straight at a suspect wall in the packaged game and read where he stops ("A room wall the camera went through (8 November 2026)"; production/audits/phase1-exit/CAMERA-WALLS-DIAGNOSIS-2026-11-08.md).

**Checks with wrong copies.** Every check row gets a wrong copy that must make its named row fail; a crash is a failing row; a control whose damage changes nothing counts as missed ("13 Oct 2026, unit 13"; "13 Oct 2026, backlog B5"; production/cloud-week/first-30-minutes/check_draft.py). Run a tool fix on real files before it counts ("Comparing two models on the same work, blind (8 November 2026)").

## 3. Traps: what failed, why, and how it was caught

1. **"Done" in the editor, absent in the shipped game.** The player's character and its movement reached the packaged game three weeks after being called done, because content loaded by name was never cooked and its folder never copied ("27 Oct 2026, a feature that only ever ran in the editor"). Masonry scans were missing from the shipped build for a month while the build machine stayed green, reading files from its own checkout ("A photographed tiling texture ... (3 November 2026)"). Pieces read as passed for days while they existed only behind test switches ("A pass must be the player's game"). Caught by the packaged log, a shipped-versus-editor picture, and the gate rehearsal. Now: the staging check and the launch-line check.
2. **A green check with nothing behind it.** The nightly walk measured nothing on three days and its picture reader looked for one file type while the tester saved another ("What came before 13 October", FAILED, Voice and talk). A witness check passed nightly by counting onlookers measured, not informed ("A town deaf to its own crime (5 November 2026)"). A collision count read -1 ("unknown") and passed as a number ("Asset checks widened to every folder that ships"). A check comparing one constant with another can never fail ("13 Oct 2026, unit 9", review fault 3).
3. **Conditions drifting between measures.** A "lost" 2 ms was mostly the picture level, because the title screen that sets it was skipped; the measure now sets and logs its conditions ("23 to 24 Oct 2026, frame headroom"). An old baseline three days older misled a saving ("Confirming a measured saving ... (7 Nov)").
4. **Watchers that wait only for success.** A pipeline cache expanded against two shader platforms' keys stopped the cook, and a two-hour wait followed because the watcher waited only for success ("23 to 24 Oct 2026, frame headroom"). A wait loop matched its own launching shell and never started a gate ("14 Oct 2026, unit 8", failed item 3).
5. **Blaming the outside load.** The "voice" frame was a shadow switch; the walk's stall was the first garbage collection ("23 to 24 Oct 2026, frame headroom"). An idle program held gigabytes of graphics memory and dropped the game from 78 to 22 fps ("27 Oct 2026, a frame-rate collapse on a build with no game change"; tools/close_games.py). A batch of compute work on a shared card cannot be pre-empted; set aside at two tries ("25 Oct 2026, a game frame held by another program's work"; production/research/frame-headroom/VOICE-ON-CARD-TRACE-2026-10-25.md). Test without the load first.
6. **Reading the wrong row.** A frame file's frame time, thread totals and render-thread stats sit on three successive rows; reading one row off called a wait unnamed ("The same stutter, its result (6 Nov)"; "A stutter traced to a sidecar and an unused system (6 Nov)"). A stutter was first closed as not reproduced from captures on an older build (same entry).
7. **A memory peak placed nowhere.** A sampler read counters a second apart, kept no series and left a child holding memory into the next capture ("A memory peak, measured before it is cut (4 Nov 2026)"; F:/LedgerTools/scratch/card-peak-2026-11-04/DIAGNOSIS.md).
8. **A tester's model of the game going stale.** The first walk on new movement passed 9 of 13 stages because the tester's pace was the old one ("27 Oct 2026, a scripted tester's steering retuned"). A seated-character proof went stale after an outfit change and found him never seated ("A side-on film of a walk at full rate"). A week of partial greetings was listed and never traced ("A tester that kept arriving late").
9. **Text compared as text.** A joined row failed only on number formatting ("-90" against "-9e+01") ("27 Oct 2026, an engine port's geography"); a table cut by awk on Windows lost every carriage return, caught by a byte comparison ("26 Oct 2026, a generated test table too big for the repository's size guard"; tools/port-golden-check.sh).
10. **Builds that only one target sees.** A header in another namespace compiled standalone and failed in the engine; build both the editor and the shipping targets ("26 Oct 2026, a rule that lived only in the engine port").
11. **Settings that did not take.** An unquoted command-line switch silently did nothing ("A pale sky and a pale far water (5 November 2026)"); one of two first tries of a launch setting never took and so was no try ("24 Oct 2026, the walk's second go"); an import's old success line proved nothing, so read the line the import just wrote ("26 Oct 2026, a room's second wear pass").

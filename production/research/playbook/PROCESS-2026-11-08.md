# Playbook: process (reference studies, research, records, the owner, sessions)

Distilled on 8 November 2026 from RECIPE.md (read in full that day). Citations give the RECIPE.md entry's date and opening words and the evidence file it names; the evidence files were not re-opened. The owner's page and messages are in `.claude/skills/his-page/SKILL.md`; the standing rules (two tries, research first, reference first) are in CLAUDE.md and RULINGS.md and are not restated here.

## 1. The method that worked

**Step zero: study two shipped games of the same kind first, ideally ones that answer the central question in opposite ways** (here one stages, one simulates). Questions written first; the games' own files only where licence and law allow; index first, extract metadata only, capped, outside the repository, one extractor at a time; every number tagged measured, read, inferred or name only, and dated; each finding a target with a check or a reason to ignore it; one fresh reviewer per study re-measures ("Step zero: study two shipped games first"; production/research/aaa-reference/REFERENCE.md and studies/). The cross-game result became day-one values ("Universal AAA starting values").

- Set-up: index every archive before unpacking; an encrypted container still shows its shape; the engine's global script container lists every system by name and seeds a coverage map that marks where each system's logic lives ("25 Oct 2026, the reference study's set-up"; DECISIONS.md 25 Oct 14:05).
- Running: bounded helpers per game extract and count; one synthesis that keeps every hedge; one fresh reviewer with the raw files and the project's own files ("25 Oct 2026, two reference studies of shipped games in one evening"; "25 Oct 2026, four more reference studies the same evening").
- Specific studies counted from data, never copied: sound metadata (no audio) ("28 Oct 2026, how two shipped games make a street sound alive"), jobs and failure ("how two shipped games build their jobs"), openings rebuilt from files ("how two shipped games open"), combat tables ("a combat reference study"), systems and small crime ("two reference studies of systems and small crime").
- Turn every recommendation into a tracked line, then have a second reader check the lines against the studies ("28 Oct 2026, every recommendation of a finished study set turned into tracked work"; production/orders/2026-10-25.md).

**Research units end in a method with its first use.** One helper per question set; each result to one fresh reviewer against its sources; faults sent back to the author; each method a numbered list of steps with a numeric check and an hour estimate ("28 Oct 2026, seven bounded research units for one order"). Read the engine's own source for what is production-ready; the code wins over the docs ("28 Oct 2026, research for building a town by generation"; production/research/phase5-procedural/RESEARCH-2026-10-28.md). Settle a source claim by counting in a throwaway project ("Counting what a cooked build really holds (7 Nov)"). When a design replaces the document a study was written against, add a comparison section, never rewrite ("13 Oct 2026, unit 7b follow-up").

**Exact targets before building, reviewed fresh.** See ENVIRONMENT for the target form; the process point is that every target in the notebook failed its first fresh review and was fixed ("13 Oct 2026, unit 8", "unit 9", "unit 13"). An exact target written by someone who does not build matched within 1.4 mm after two tries ("What came before 13 October", PROVEN; production/lab/LAB-REPORT.md section 2).

**Design drafts as readable rows.** Fix the newcomer, the clock and the cost cap; define the words the draft is judged in; write each route as rows a program can read so every measure is counted from them; quote every line from a home; list what the build lacks as a count ("13 Oct 2026, backlog B5"; production/cloud-week/first-30-minutes/DRAFT.md). Side stories from the reference games' job structure and one filter (every ending changes what someone knows or says), givers from existing cast sheets, one fresh reviewer against canon and the main outline ("Side stories as a ruled list (8 Nov 2026)"; production/research/side-stories/REVIEW-2026-11-08.md).

**Records with one home and a check.**
- Order ledger: one line per item with a stable id and a status from a short list; anything not done or dropped reappears in the next order; checked against the version being replaced, in the push hook and the build checks; the owner's page derived from it ("25 Oct 2026, an order ledger"; tools/order_ledger.py).
- One standing page for the owner's open decisions, rebuilt from one data file, taps stored per item and read before asking again ("One standing page for the owner's open decisions (2 November 2026)"; tools/needs_you_page.py).
- Caps on what is read most: entry counts where the rule is a number of items, words where it is length; merge or archive, never drop ("Caps on the records read most (8 Nov 2026)"; tools/doc-caps.py).
- A handover's "found" list closed against the home of each fact, changing the derived thing, never the home ("21 Oct 2026, item 5: a handover's 'found' list closed against primary sources").
- Write past work up from the records in order of authority, each line with its evidence file ("13 Oct 2026, unit 14").

**The owner's taste by pictures, then measurement.** Show choices as pictures from the shipped build with their numbers; set his pick in one spec; when his note asks for something, measure each candidate in the shipped build; when asks cannot all hold, show the cost ("28 Oct 2026, a camera distance chosen by the owner from pictures"; production/specs/camera.json). Anything about taste or identity becomes a choice for the owner, shown in the product first ("28 Oct 2026, three small reference studies (camera, interface, pipeline)").

**Sessions and spend.** Measure a fresh session's start from its own log before cutting; split standing records so the start reads rules, state and open asks; a session cannot start another, so one hourly gate starts work only when the last has stopped ("A lean start for a fresh working session (4 Nov 2026)"; tools/fresh_gate.py, production/audits/lean-start/QUALITY-WEEK-2026-11-04.md). Test the whole sequence, killed session then repeated waits ("A take-over that survives a killed session (7 Nov)"). Price each step from the logs ("Handover cost measured (5 Nov)"; "Six spend measures and a stop aligned to the next run (5 Nov)"; tools/handover_cost.py, tools/token_measures.py). Compare a cheaper model blind on about five recent items in light shared clones, one judge of the stronger model ("Comparing two models on the same work, blind (8 November 2026)"; production/research/token-audit/SONNET-BLIND-REPLAY-2026-11-08.md).

**Editor connection, read-only first.** The engine maker's plugin at project scope, tool-server plugins named only on the command line, the server registered in local scope, commit before every editor session, first calls read-only ("21 Oct 2026, item 4: an AI session connected to the live game editor"; production/cloud-week/research/1e-unreal-mcp-setup.md).

## 3. Traps: what failed, why, and how it was caught

1. **An uncapped extraction.** One study's raw exports (26 GB) filled the shared disk; five studies lost part of one game's data, and another study lost its raw exports when they were removed before its review ("Step zero"; "28 Oct 2026, how two shipped games open"; "a combat reference study"; "how much a believable town says"). Rule since: cap and place every extraction, one extractor at a time, delete only after the review.
2. **Comparisons with the project's own state.** In three of four studies the heaviest review fixes were in what was said about the project itself ("25 Oct 2026, four more reference studies"); a dropped hedge carried a whole recommendation and advice broke a standing ruling ("25 Oct 2026, two reference studies ... in one evening"). Give reviewers the project's research and code too.
3. **Numbers from memory or history.** Three cost lines had to be corrected; take times from the clock ("25 Oct 2026, four more reference studies"). A past cuff size was double-counted; numbers from one's own history need the same re-measure ("28 Oct 2026, seven bounded research units"). A source cited for a number was the wrong document ("13 Oct 2026, unit 6.1b"). Lines written from what a name suggested, not what the file holds ("13 Oct 2026, unit 14").
4. **A chained session design.** A scheduled run may not start another; the first take-over design tested each piece alone, never the sequence, and about ten hours were lost before the fix ("A lean start for a fresh working session"; "A take-over that survives a killed session (7 Nov)").
5. **Reading only the latest rulings.** Frame colours went against a standing ruling because only the latest were read and a photograph tally settled it ("13 Oct 2026, unit 8"); an object the owner had removed was put back ("unit 13", review fault 3).
6. **Working from a summary.** A helper was briefed from a summary because the design document was thought unreadable; it was in the owner's document list ("13 Oct 2026, unit 7b follow-up"). List every place the owner keeps documents first.
7. **A key left behind.** A study helper's backup of the viewer's settings kept a game's file key on the system drive; found and blanked ("28 Oct 2026, seven bounded research units").
8. **Getting round a refusal.** A brief wrongly sent a helper to retry a refused site with a browser identity ("What came before 13 October", FAILED; DECISIONS.md 13 Oct 04:45). Refused pages are listed, not worked round.
9. **Caps that hide growth.** A word cap alone let the faults list grow past its count ("Caps on the records read most"); the decisions log reached 23,600 words in ten days and sessions skimmed ("What came before 13 October", FAILED).
10. **Content reaching into the main story.** The first side-story draft let consequences touch main-story beats, left endings with nothing kept, and tagged sizes the steps did not support; a reviewer reading the outline caught it ("Side stories as a ruled list").
11. **Helpers' content that knows too much.** Town content gave people other people's secrets; ambient lines claimed what the street thinks or led to places that do not exist; a word list written to six examples caught only those six ("What came before 13 October", PROVEN, The simulation; production/cloud-week/REVIEW-canon-11-12-B5.md).
12. **Health from memory.** A health check read from memory missed that two of three scheduled jobs had not done their work; read the scheduler's own records ("25 Oct 2026, an order ledger").
13. **Shell traps.** A heredoc ate backslashes of a hook and a table ("25 Oct 2026, an order ledger"); a helper's edit left mixed line endings ("Porting one simulation rule set", 6 Nov).

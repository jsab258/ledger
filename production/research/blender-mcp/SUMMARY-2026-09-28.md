# Driving Blender live over MCP (28 September 2026)

The problem (Jafar, 28 September): connect Blender live to Claude Code through an MCP connection for this week's street clutter; an official one if there is one, otherwise the most widely used open one, after checking its licence and what it can access. Researched by a separate helper; installed and tested by the builder.

## What was found

- **Official: "MCP Server", Blender Lab** (the Blender developers): https://www.blender.org/lab/mcp-server/ ; code https://projects.blender.org/lab/blender_mcp (v1.0.0 27 April 2026, v1.0.3 11 September 2026). Licence GPL-3.0-or-later (the add-on's manifest). Needs Blender 5.1 or newer. Two parts: a Blender add-on that listens on localhost:9876, and an MCP server (`blender-mcp`, run with `uv`) that Claude Code starts over stdio. Anthropic announced it as an official Claude connector on 28 April 2026: https://www.anthropic.com/news/claude-for-creative-work
- **What it can reach:** 26 tools, among them `execute_blender_code`, which runs any Python inside Blender, so through Blender it can reach files and the network; Blender's own page warns the code runs without guards. Nothing found shows it contacting outside services, and it has no telemetry. The add-on starts its server only when Blender's online access is allowed.
- **Community alternative: "MCP for Blender" (ahujasid)**, MIT, about 29,500 stars, Blender 3.0 up, latest 2.1.1 (27 September 2026): https://github.com/ahujasid/blender-mcp . Telemetry on by default (to Supabase), optional outside asset and generation services, four CVEs in 2026 (e.g. https://github.com/advisories/GHSA-qqw9-95ww-prfm ). Not chosen.
- **A new MCP server loads only when a Claude Code session starts**; `/mcp` reconnects only servers already loaded. Requests to change it were closed: https://github.com/anthropics/claude-code/issues/40059 (28 March 2026), https://github.com/anthropics/claude-code/issues/46426 (10 April 2026).
- Known Windows problems in the official one: Smart App Control can block its unsigned blender-mcp.exe (not set on this PC); the `*_for_cli` tools can hang.

## What was done

- Blender 5.2.2 LTS, portable, on F:/LedgerTools/blender52 (checksum matched blender.org's), beside the 4.5 the scripts use; its settings stay in its own `portable` folder.
- uv 0.12.19 on F:/LedgerTools/uv (checksum matched), with its cache and any Python it fetches kept on F:.
- The official server at v1.0.3 in F:/LedgerTools/blender_mcp; the add-on built and installed, enabled, into the portable Blender (auto-start on by default).
- Registered with Claude Code for this project only (`claude mcp add-json blender ... --scope local`); Claude Code's check reads "Connected". It loads from the next session.
- Tested end to end the same day: Blender started with `--online-mode` (this run only; no saved setting changed), the server listed 26 tools and `execute_blender_code` added a cylinder. Start Blender for it with tools/blender-live/start-blender-live.ps1.
